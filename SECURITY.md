# Reporting a security vulnerability

Please do not publish exploitable security details in a public issue or pull request.

## Preferred reporting route

If GitHub's **Private vulnerability reporting** feature is enabled for this repository, use the repository's **Security** tab and submit a private vulnerability report.

If private reporting is unavailable, contact the repository owner privately through an established GitHub contact channel. Do not post credentials, proof-of-concept payloads targeting real users, private messages, database exports, or personal data in public.

## What to include

- A concise description of the affected feature and potential impact.
- The affected commit or version, if known.
- Reproduction steps using a local instance and synthetic accounts.
- A minimal proof of concept that does not access, alter, or disclose another person's data.
- Any practical mitigation you have identified.

## What to expect

Please allow the maintainer reasonable time to acknowledge, investigate, and coordinate a fix before public disclosure. There is currently no published security-response SLA or staffed security team; do not assume continuous monitoring or guaranteed response times.

Do not perform destructive testing, denial-of-service testing, social engineering, or testing against other people's accounts or production data. Stop if you encounter data that is not yours and report the issue without retaining or sharing it.

## Scope and limitations

This channel is for vulnerabilities in Pinglet's code and deployment configuration. It is not an emergency support channel. The project has not claimed an independent security audit, and its message-encryption design is experimental; see the README for current limitations.
